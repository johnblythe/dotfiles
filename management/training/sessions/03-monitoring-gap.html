the pattern

Symptoms fire. Causes don't.

This isn't just PDFWorker. It's the most common monitoring gap across all our services.

🌡️

Symptom Monitors

Queue depth, timeouts, DLQ messages, pod restarts, downstream failures. We have these.

🔬

Cause Monitors

Error rates, latency percentiles, resource exhaustion, dependency health. Often missing.

💡 Claude's /monitoring-gap skill is trained to spot this pattern and fix it automatically.

step 3 · terraform

Three files. Production-ready.

Claude follows the existing Terraform patterns in your repo — same module structure, same naming, same tags.

📄 custom_application_monitors.tf
resource "datadog_monitor" "pdfworker_error_rate" {
name = "[healthsource] PDFWorker Error Rate is too High"
type = "query alert"
tags = concat(["service:hs-pdfworker", "team:healthsource"], ...)
priority = 1
 
query = <<-EOT
sum(last_5m):(
sum:trace.listener.new_message.errors{...}.as_count() /
sum:trace.listener.new_message.hits{...}.as_count()
) * 100 > ${var.monitors...critical}
EOT
 
# Investigation steps, APM links, Slack notification
message = <<-EOT ... 20 lines ... EOT
}

reference · thresholds

How Claude picks the numbers

The skill uses threshold guidelines based on service criticality. You can always override.

Service Type Warning Critical
User-facing (CIPUI) 5% 10%
API services 10% 25%
Background workers 25% 50%
Batch processing 50% 75%
📐
PDFWorker is a background worker → warn at 10%, critical at 50%. Claude defaulted to these, but asked before committing.
patterns

Gaps the skill catches

📊

Queue depth without error rate

The queue backs up because something is failing upstream. Monitor the failure, not just the backup.

⏱️

Timeouts without latency monitors

Requests time out because p95 latency is creeping. Catch the creep before it becomes a cliff.

☠️

DLQ messages without processing failures

Messages land in the dead letter queue because processing failed. Monitor the processing.

🔄

Pod restarts without OOM/resource alerts

Pods restart because they ran out of memory. Monitor memory, not just the restart count.
