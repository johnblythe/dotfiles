the incident

INC-1243: Requests stop
becoming workable.

Feb 25, 2026. HealthSource requests that normally process instantly start taking 30+ minutes. Customers miss SLA deadlines. The incident lasts 33 hours before the root cause is fixed.

SEV-2 · 33 HOURS · CUSTOMER-REPORTED
📉

Unindexed Query

A bad query on ereq_location_option hammered the DB. An FE deploy increased its usage.

💥

Pod Explosion

eipasyncprocessor bloated from 2 to 12 pods the Friday before and never scaled back down.

🚫

Scaling Failure

requestworker stuck at 4 pods. HPA didn't trigger. The critical service couldn't keep up.

🚨
Detection was human, not automated. Danielle reported the incident based on customer complaints. No monitor, alert, or dashboard fired first. The retro says plainly: "We do not have monitoring enough to know that there's a problem."

step 3 · prioritization

Pick three. Ship today.

"Pick three based on what gets us the most high impact for the least effort." Claude selects three monitors that are pure Terraform — no code changes, no deploys, just config.

🔴

Postgres CPU

HEAL-2397. Root cause signal. One Azure metric. Warn at 80%, critical at 90% sustained 10min.

🔌

Connection Failures

HEAL-2398. Cascade trigger. Fires when the DB starts rejecting connections — the first domino.

📈

HPA at Ceiling

HEAL-2399. Scaling failure. Fires when any critical service HPA is maxed out for 10+ min.

✅
Why these three? All are pure Terraform — no application code changes, no service deploys. They deploy via the existing Atlantis PR workflow. Maximum signal for minimum risk.
step 4 · terraform

Writing monitors that match
existing conventions.

Claude read the existing Terraform module, matched the for_each pattern, variable structure, and alert routing — then wrote three new resources across four files.

⚙ modules/datadog-hs-monitors-v2/azure_postgres_monitors.tf
resource "datadog_monitor" "azure_postgres_cpu_utilization_monitor" {
  for_each = var.azure_postgres.cpu_utilization.servers
  name = "[HealthSource] Azure Postgres CPU > ${...threshold}% on ${each.value.name}"
  type = "metric alert"
  query = "avg(last_10m):avg:azure.dbforpostgresql_flexibleservers.cpu_percent{
            resource_name:${each.value.resource_name}} > ${...critical}"
  message = "{{#is_alert}} Postgres CPU is critically high..."
  # ... thresholds, tags, evaluation_delay, notify_no_data
}
⚙ modules/datadog-hs-monitors-v2/k8s_monitors.tf
resource "datadog_monitor" "hpa_at_max_replicas" {
  for_each = var.k8s.hpa_at_max.deployments
  name = "[HealthSource] HPA at max replicas: ${each.value.name}"
  query = "max(last_10m):(
    kubernetes_state.hpa.max_replicas{...}
    - kubernetes_state.hpa.current_replicas{...}) <= 0"
  # Covers: requestworker, audittrailworker, pdfworker, intakequeueservices
  # References INC-1243 pattern in alert message
}

Paste any retro doc

Incident retros, post-mortems, on-call handoffs. Ask: "What signals could have caught this? Do we monitor any of them?"

🎫

Ask for tickets

"Make an epic and ticket all the gaps." Claude handles the Jira wiring — epics, links, labels, initiative connections.

Ask for implementation

"Pick the best bang-for-buck and write the code." Claude reads existing conventions and writes code that fits.
