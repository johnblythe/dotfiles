Discovery #1: Two Populations Hiding in "Logging"

The median logging time is meaningless without segmenting by intake channel

1 sec
Median for ELECTRONIC / PULLLIST / MANUAL

Why? Not "good STORK" — data arrives pre-structured. Electronic = portal/EMR integration (fields pre-filled). PullList = spreadsheet auto-parsed. Manual = CSR entered data at creation. No logging needed.

19-142 min
Median for UPLOAD / CENTRAL INTAKE

Why? These arrive as scanned PDFs. ADE (OCR+NLP) reads the request letter, but a human logger must validate/correct every field, search for requester, enter patient info, set dates of service, etc.

Intake Channel Glossary

UPLOAD = PDF uploaded by CSR (preferred) · CENTRAL INTAKE = Centralized team splits scanned batches · ELECTRONIC = Portal/EMR structured data · PULLLIST = Spreadsheet bulk (HEDIS, MRA) · MANUAL = "Add New Request" by CSR

Why CLIN is Fastest

Clinical requests come from other hospitals/doctors. Request letters are structured, professional forms with clear patient info, specific dates, standard record types. ADE (OCR) reads them well. Logger mostly validates.

Why ATTY is 3.5x Slower

Attorney requests mean dense legal language, broad date ranges ("any and all records"), fee approval handling, sensitive data flags, non-standard authorization forms. Logger does heavy manual entry.

The Implication

Averages are misleading. The taxonomy treats all requests the same. They're not. ATTY at P75 takes 18.8 hours. CLIN at P25 takes 54 minutes. That's a 21x spread.

Discovery #6: 65% of Rework Time Is Queue, Not Work

The bottleneck isn't how long work takes — it's how long requests sit waiting between stages

Happy Path (Clean Pass): 2.8h total

Rework Paths: Where the Time Goes

The Pattern

A redo request's life:

  1. Logged in 54 min (active work)
  2. Moves to QC — reviewed in 10 min
  3. Sent to redo queue, sits for 6.6 hours
  4. Picked up, redo takes 16 min
  5. Moves forward again

1.5h of work. 10+ hours of waiting.

New telemetry won't fix queue time. This is a routing and staffing problem. The highest-ROI intervention is reducing the 6-7 hour gap between "redo flagged" and "someone picks it up."

Recommended Path Forward

Phase 0: Dashboards (Now)

Build on existing data — zero instrumentation:

  • Logging TAT by channel × major class
  • Rework rates (human-worked only!)
  • Exception frequency and duration
  • Patient lookup NotFound rates
  • End-to-end cycle time by segment
  • Fulfillment TAT by source type

Cost: SQL + Sigma/Looker dashboards
Time: 1-2 weeks
Impact: Immediate visibility

Phase 1: Quick Wins (2-4 weeks)

Fix known issues — no new telemetry needed:

  • Pre-validation: Check address + patient name before workflow (fixes 36-70% of Field Input / Invalid exceptions)
  • Verify tuning: Filter doctor/nurse + medical terms from name matching (reduces 69% false positives)
  • Auto-routing: DAR relog, site moves, pull list (eliminates ~24% of resubmissions)

Scope: UPLOAD + CENTRAL INTAKE only
Impact: Reduce queue time by preventing rework
Justification: Data already proves these are the causes

Phase 2: Targeted Instrumentation

6-8 net-new events for actual gaps:

  • STORK edit tracking (what ADE got wrong)
  • Intra-session form field timing
  • Chart image rejection root causes
  • Processor active/idle time (tab focus)

Prerequisite: Phase 0-1 validated
Justification: Data-driven, not speculative
Avoid: 7-9 weeks of plumbing first

Start with what you have. Instrument what you can't see. Build infrastructure when you've proven the value.
