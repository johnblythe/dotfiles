Friction

The Bus Factor Problem

Each workstream is owned by 1-2 people. No cross-training. No backup.

When someone's out

It's not "second string steps in."

It's the running back playing wide receiver.

A different position. Different skills. Different playbook. The work doesn't just slow down — it stops.

This also explains stuck reviews

  • Nobody else knows the workstream well enough to review it
  • Reviews sit because the only qualified reviewer is the author's neighbor — and they're busy
  • Knowledge silos compound: less review → less shared understanding → fewer reviewers
Not anyone's fault. It's how the work naturally siloed. But it's a risk we can start reducing.

Part 3

Three Tweaks

Not new process. Just making what works visible —
and removing what slows you down.

Tweak 1

Write It Down

The ask

Before moving to In Progress, define:

  • Input — what data/state to start with
  • Output — what "done" looks like
  • Touchpoints — which files/services change

Not a novel. A recipe card.
~15 min per ticket. Saves hours downstream.

You're already doing this

Ben's tickets have schema DDL, method signatures, file paths. That's why his workstream is at 50% burn.

Ben already does this Nina's close

What it unlocks

61% of sprint work is Claude-assistable — but only if the spec exists. This one tweak makes ~24 pts/sprint of boilerplate acceleratable.

Tweak 2

Review It Fast

The ask

48-hour SLA on code reviews.

Not merged in 48h. Reviewed. First pass, comments posted.

  • Each workstream gets a named reviewer
  • If 48h passes, call it out in standup
  • Smaller PRs (from Tweak 1) = faster reviews

The current cost

13
Items stuck in review
~30
Points of finished work on a shelf

What it unlocks

Dependency chains flow. WIP drops. Sprint burns become predictable. Engineers feel momentum instead of waiting.

Tweak 3

Let Claude Handle the Boilerplate

Work TypeClaude DoesEngineer Does
Migration DDL Generate SQL + mapper from schema Review, adjust, test
Test scaffolds Generate suite from signatures Define scenarios, validate
Service skeleton Generate class + method stubs Implement business logic
Config patterns Apply existing pattern to new endpoints Verify behavior
Systematic renames Find-replace across codebase Verify no semantic changes

What it unlocks

15-20 pts/sprint of engineer time freed for design and integration. Engineers own the output — Claude drafts, you ship.

The System

They're a Flywheel

1. Write It Down

Good specs enable Claude assistance AND faster code reviews.

→ feeds Tweak 2 & 3

2. Review Fast

Unblocks dependency chains. Reduces WIP. Predictable burns.

→ smaller PRs from Tweak 1

3. Claude Boilerplate

Produces focused PRs that are easier to review. Reinforces spec patterns.

→ feeds Tweak 1 & 2
Not three separate asks. One system where each piece makes the others easier.
