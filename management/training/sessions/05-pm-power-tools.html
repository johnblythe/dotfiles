Ask Data, Get SQL

Ask a plain-English question. Get the answer AND the SQL — so you learn the patterns over time.

~/code/healthsource
/snowflake-explorer how many requests came in last week by source type?
 
Claude
Reading schema from telemetry-deck/SCHEMA.md...
Generating SQL...
 
Here's what I'll run:
SELECT SOURCE_TYPE,
COUNT(*) AS request_count,
ROUND(COUNT(*) * 100.0 / SUM(COUNT(*)) OVER (), 1) AS pct
FROM erequest_dynamic
WHERE CREATED_DT >= DATEADD('day', -7, CURRENT_DATE)
GROUP BY 1 ORDER BY 2 DESC;

Just Ask the Code

No special command needed. Just ask questions like you'd ask an engineer.

~/code/healthsource
Why would a request get stuck in Logging Exception?
 
Claude
Searching codebase for exception handling in logging workflow...
Reading services/workflow/LoggingExceptionDelegate.java
Reading services/workflow/fulfillment-subprocess.bpmn
 
A request enters Logging Exception when:
 
1. Missing required fields — the ExceptionRuleEvaluator
checks 48 reason codes (e.g., "Field Input Required",
"Invalid/Incomplete Request")
2. Correspondence needed — requires outbound contact
before logging can continue
3. Manual flag — processor marks it via QueueServiceImpl
 
It stays stuck when IS_REMOVED = 0 (exception not resolved)
and no one re-queues it. The workflow timer in the BPMN
doesn't auto-escalate — it just waits.
 
Key files:
services/workflow/LoggingExceptionDelegate.java:42
services/workflow/fulfillment-subprocess.bpmn:189
services/intakeservices/ExceptionRuleEvaluator.java:78

Now you walk into that support call already knowing the code path. No pre-meeting prep. No waiting on an engineer's availability.

Shape

Shape Before You Solution

The biggest PM trap: jumping to solutions before understanding the problem. These tools force the right order.

💭

Brainstorm First

"Let's brainstorm approaches to intake acceleration" — explores the problem space, surfaces options you hadn't considered, before anyone writes a line of code.

📐

/shaping

Structured problem-solution methodology. Requirements (R), shapes (A, B, C), fit checks, breadboards. Keeps you from falling in love with the first idea.

🗺️

/breadboarding

Map how existing systems actually work. UI affordances, code affordances, wiring. Reveals where changes actually need to land.

📋

Write a Plan

"Write an implementation plan for this spec" — turns requirements into structured, sequenced work breakdown. Share with eng for instant alignment.

🔑
The PM superpower here isn't the tool — it's the discipline. Shaping forces you to enumerate requirements before evaluating solutions. That's how you avoid rework and "wait, what about..." three sprints in.

Getting Started

Monday Morning

From zero to querying data and reading code in under 10 minutes.

1

Run the setup script

Installs SnowSQL, configures your connection, copies skills and CLAUDE.md into place.

cd ~/code/management/jim-package && ./setup.sh

2

Open Claude Code in the healthsource repo

This is your home base. Claude can see all the code from here.

cd ~/code/healthsource && claude

3

Try your first question

Start with something you'd normally Slack an engineer about:

What does the intake service do when a fax comes in?

4

Try your first data question

Something you'd normally wait for a dashboard or analyst:

/snowflake-explorer what's the exception rate by reason this month?

The Compound Effect

Every question you ask the code, every SQL query you see, every system you map — it compounds.
