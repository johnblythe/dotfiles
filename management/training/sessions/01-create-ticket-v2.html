Set up safe, read-only database access for Claude Code across QA01 and local environments so engineers can query schema/mapping data without manual permission grants or token-burning schema discovery.

Scope

  • Create a Postgres permission set (not a shared user) with SELECT-only grants on tables — no proc/function execution
  • Each engineer gets their own claude_<name> DB user inheriting the permission set
  • Grant SELECT on information_schema so Claude can self-discover table/column names
  • Configure for both QA01 and local environments
  • Document setup in Confluence / team toolbox

Nice-to-Have

  • Claude skill or MCP config that pre-loads schema metadata (e.g., point at alembic migrations) to reduce token burn

Context

Slack thread (Jeff N, Jonathan Falkenstein, Michael Sakaluk): engineers want Claude to query mapping data but current setup requires per-query permission approval and Claude lacks schema awareness. Consensus: read-only permission set, per-engineer users, no write/proc access.

Your Turn

Tips for Best Results

📋

Don't Clean the Paste

Raw Slack copy-paste is fine. Timestamps, usernames, emoji reactions — Claude handles it all. The more context, the better the ticket.

🎯

Name the Target

Tell Claude the sprint, project, or epic. "ROIP.Q1.S3 at 0pt" gives it enough to fill every field. If you skip this, it'll ask.

✏️

Use the Review Gate

Claude always shows you the draft before creating. Don't just say "go for it" — read the description. Tweak the summary. The 5 seconds is worth it.

🔗
Not just Slack: Paste from anywhere — meeting notes, email threads, a paragraph from a PRD, even your own stream-of-consciousness. Claude synthesizes.
